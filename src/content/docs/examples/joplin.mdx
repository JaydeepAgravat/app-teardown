This is the third real teardown, run the same way as the [Bluesky example](/examples/bluesky/) and the [Expensify example](/examples/expensify/): probes on an emulator, outcomes recorded in the worksheet, and every conclusion then checked against source code the app's maker publishes.

Joplin was chosen for two reasons. It is a third kind of design. Bluesky keeps its data in memory, Expensify keeps an offline replica of a backend, and Joplin keeps the only copy on the device and syncs only if the user picks a place to sync to. On the test device no sync target was set, so the app had no backend at all. The second reason is coverage. The first two runs tried the probes most likely to matter. This run went through all 443 probes and ran every one that a single emulator allowed.

More probes meant more errors. Nine readings were contradicted by the source, and all nine are listed here with what was changed.

:::note[Why a real app is named here]
The chapters name no products. The worked examples are the exception. What was seen carries a confidence word. What is said about the app's internals comes from source code its maker has published.
:::

## The nine wrong readings, and what changed

Eight of the nine have the shape seen with Expensify: the behavior was recorded correctly, and the reading named one design where several fit. The ninth, P54.4, was partly the run's fault.

**1. P8.6 and P8.7 saw a screen under the link target and called it built for the target.** In both, the note list under the note was the last notebook used, not the note's own notebook. That detail was recorded, and it is exactly what separates a synthesized stack from a target pushed over the start screen. The readings did not ask for it. They now do.

**2. P9.6 assumed rotation rebuilds the screen.** An app can tell the operating system that it handles the change itself, and then nothing is rebuilt and nothing needs to survive. The reading now names both and says they look the same from outside.

**3. P12.3 assumed every durable offline change sits in an outbox.** That is the design of an app whose backend is the source of truth. A local-first app has no queue of mutations. Its local store is the truth and sync compares state. The reading now names both. This is the most important correction of the nine, because it was a blind spot in [Chapter 12](/part-2-concerns/12-offline-and-sync/)'s probes and not a slip in one sentence.

**4. P54.4 said process death cannot lose more than the last keystroke.** It can lose about half a second. The probe was recorded from the runs with a pause, in which everything survived, although the runs without a pause had lost text. The reading now tells you to repeat with an immediate quit, and to treat what is lost as the length of the save delay.

**5. P37.8 offered two designs and the true one was a third.** The times are formatted on the device at display time, with a zone that the app's runtime read at launch. The reading now lists it, with the test that points to it: the "refresh" that works is a restart.

**6. P22.2 read a silent failure as missing code.** A branch that logs and returns looks the same as no branch. A branch that failed to show looks the same too. The reading now says only what the user can see.

**7. P3.4 turned "no remote media was seen" into "no media delivery".** One device in one configuration cannot show that. The reading now says so.

**8. P4.1 assumed that storage which grows was filled by browsing.** Here it grew by writing. The reading now separates the two by which figure grows and by what you were doing.

One probe was run wrongly before it was run rightly. P37.6 was first run with the app's own language setting, which changed the text and mirrored nothing. The source showed that direction follows the device's language. A second run with the system's per-app language mirrored the whole layout. The probe's step now says which setting to use, and to try the app's own as a separate run.

All of these corrections are in the chapter data.

## What else the method missed

- **Three things seen that no outcome describes.** The empty-list text that flashes on every cold start (P7.2). A form whose only validation is a disabled save control (P21.7). A list of attachments with sizes that is not a storage screen (P36.6). They are listed as skipped, since no outcome matched.
- **Two defects that are not designs.** After the system's per-app language was changed while the app was running, the app stopped responding to touch until it was force-quit. This was seen once. An alarm notification came back at each launch after its to-do was ticked. Neither was traced in the source.
- **Sync, which is half of this app.** With no sync target allowed, nothing was learned about conflicts, first sync, encryption or attachment download. Chapter 12's two-device probes are where that design would show.
- **The store listing.** Thirteen probes read the store page or compare with other apps. The store was not opened on this device.
- **The technology, again.** The probes found that the note viewer is web content. They did not find that the rest is a cross-platform toolkit, which the source shows at once.
- **Low coverage where it looks high.** Of 443 probes, 53 ran. Most of the rest need a second device, a backend, days of waiting or a feature this app does not have. A run on one emulator cannot do better with this app.
